# A useful first result

Use for a broad fund assessment or requested synthetic walkthrough, not a narrow
question. Start when the user has asked for analysis and legitimate inputs are
available. Resolve only uncertainties affecting this assessment, using the existing
import/confirmation rules. Do not ask the user to select algorithms or reconfirm
their request. A bare attachment is not an instruction to analyze it.

## Performance and losses first

Use the supported summary calculations for annualized return, annualized volatility
and maximum drawdown where eligible. Add one cumulative-return or drawdown chart
that best supports the main finding. Reuse available result objects and obtain
chart data only when needed. This is an output pattern, not a fixed endpoint list,
call quota or alternative calculation method. Do not invent missing metrics or
calculate replacements in conversation. Keep valid results when one metric is
unavailable; explain only the limitation that matters.

For several funds, use one compact matched-period comparison and a shared chart.
Preserve the requested selection, distinguish full histories from the common
sample, and explain any material exclusions. No separate report for every fund,
automatic winner, invented benchmark or unsupported portfolio reconstruction.

Lead with the main finding, then a small table and one chart where the host supports
it. Explain what the result means in a few sentences. Keep actual dates, frequency,
currency/return basis and material limitations visible without a technical preamble.
Label synthetic inputs clearly. A compact answer is the aim, not a rigid word count;
do not omit an important caveat to shorten it or claim a chart exists before rendering.

## Follow the finding

Offer at most one useful next investigation, tied to the evidence. Examples:

- A large loss: examine duration and recovery.
- Similar fund performance: investigate whether losses occur together.
- A question about return drivers: use the appropriate factor analysis.

Do not precompute rolling analysis, factor models, attribution or public research
for possible later use. Run them when requested or when the user chooses that
follow-up. Do not shorten their period to make a calculation complete. Supporting
documents can be suggested when they address a specific uncertainty, not as an
onboarding requirement. After a synthetic example, the next step can be the user's
own data. Stop when the question is answered.

If the original request specifies factors, rolling results, a portfolio question
or a full diagnostic, follow that request directly using the relevant guidance.
Users can change direction at any point; there are no prerequisite tour stages.
